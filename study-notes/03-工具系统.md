# 第 3 层 · 工具系统 学习笔记

> 文件：tools/registry.py（67 行）、tools/calculator.py、tools/ask_user.py
> 对照脚本：day3_demo.py（手动跑一遍 ReAct）、day3_experiment.py（schema 实验）

## 一、工具的两个半身

- **schema（菜单）**：`{"type": "function", "function": {name, description, parameters}}`
  随请求发给模型，模型只能看到这部分。
- **executor（厨房）**：真正干活的 Python 函数，模型永远看不到实现。
- 两个半身通过 `registry.TOOL_EXECUTORS` 字典绑定：名字 → 函数。

## 二、JSON Schema 约束

- `parameters`：type: object + properties + required。
- 关键认知：schema 的 name/description **不是文档，是 prompt 的一部分**，
  直接决定模型会不会用、什么时候用、参数填什么。
- 实验结论（day3_experiment）：无 description 模型无从判断；
  无意义名字（tool_xyz）模型不用。
- 手艺要点：description 写"何时用"，参数 description 写"填什么"。

## 三、注册表 = 副作用收口

```python
TOOL_EXECUTORS = {"calculator": calculator.execute_calculator, ...}
get_tool_schemas()   # 打包所有菜单发给 API
execute_tool(name, args)  # 唯一执行入口：查表 → 执行
```

- 单一入口：权限、审计、日志都可以插在这里。
- 兜底分支：模型点不存在的工具（幻觉）→ 返回"未知工具"而非抛异常。
- register_dynamic：MCP 动态注册口子（静态字典 + 动态字典双层查找）。

## 四、防御性执行（信任边界）

- 模型输出 = 不可信的用户输入。schema 声明 string ≠ 内容无害。
- calculator 范例：`eval` 前白名单正则 `re.fullmatch(r"[0-9+\-*/().%\s]+")`，
  否则 `eval("__import__('os').system(...)")` 可执行任意代码。
- 每个工具 executor 第一行都是防御：类型转换、白名单、try/except。

## 五、交互即工具

- ask_user：把"向用户提问"包装成标准工具——input() 阻塞等答案，
  答案走标准 tool 回填通道。loop 无需特殊处理。
- 统一协议的价值：任何能力（计算、提问、搜网、跑命令）接入后
  对模型都是一样的"点单→结果"。

## 六、思考题与答案

**Q1：为什么模型只能看到 schema 而看不到 executor 实现？**
A：架构上天然如此——executor 跑在本地进程，API 只传输 schema 文本。
这带来两个好处：① 安全边界：模型无法读取工具实现、无法探测
文件系统细节（如 _safe_path 的圈定逻辑）；② 解耦：改 executor 实现
不需要重新训练/微调模型，只要 schema 语义不变，模型行为不变。

**Q2：execute_tool 遇到未知工具为什么返回字符串而不是抛异常？**
A：模型可能幻觉出不存在的工具名。如果抛异常，会炸掉整个 run_loop，
用户这一轮直接报错（main.py:428 捕获）——一个幻觉就废了一轮对话。
返回"未知工具: xxx"作为 tool 消息回填，模型看到后会自动纠正，
换一个真实工具。**把模型的可纠正错误留在对话循环内消化**。

**Q3：calculator 用了 eval，为什么说它安全？**
A：eval 本身极其危险（可执行任意 Python）。安全来自前置白名单：
`re.fullmatch` 只放行数字和运算符字符，任何字母（包括 __import__、os）
都进不来。安全模型 = 先白名单过滤 + 后执行，而不是执行后补救。

**Q4：ask_user 为什么设计成工具而不是 loop 里的特殊分支？**
A：如果做成 loop 特殊分支，loop 就要知道"什么情况该问用户"，
而"该不该问"本质是模型的语义判断（歧义检测），不是 harness 能
机械判定的。做成工具后，模型自主决定何时提问，harness 的
"执行工具→回填结果"通道原样复用，零特殊代码。**把智能留给模型，
把机制留给 harness**——这是全书的通用设计原则。

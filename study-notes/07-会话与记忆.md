# 第 7 层 · 会话与记忆 学习笔记

> 文件：agent/session.py（120 行）、main.py 记忆部分（83-176, 289-318, 462-489）
> 示例：user_memory.md

## 一、三段式存档（session.py:59-85）

- save_session → 写临时文件 `.tmp_{id}.json`
- commit_session → `os.replace` 原子替换成正式文件
- discard_session → 删临时文件

动机：
1. 退出时用户要选择"保存/丢弃"，先写临时、后决定。
2. 防写一半崩溃：os.replace 原子，绝无半个 JSON（先写后改、原子提交）。

## 二、sanitize_messages：孤儿 tool_calls 清洗（session.py:38-56）

- 场景：点单后审批被中断，留下无结果的 assistant(tool_calls)，恢复后 API 400。
- 逻辑：扫到带 tool_calls 的 assistant，收集其后 tool 消息的 id；
  `ids <= found`（点单全覆盖）才保留整块，否则整块丢弃。
- 精妙点：用子集 `<=` 而非相等 `==`；assistant+tool 必须成对整块处理。
- 与第 5 层"拒绝也回填"是一件事的两端：一个"制造结果让配对完整"，
  一个"删掉无法配对的点单"。

## 三、_strip_images

- 图片 data_uri 巨大，存档替换为 "[历史图片已移除]" 占位文本。
- 呼应第 2 层 _strip_history_images：运行时省上下文，存档时省磁盘。

## 四、两层记忆

- 全局 user_memory.md：跨项目偏好（称呼、风格）→ 跟"你这个人"走。
- 项目 .mini-harness.md：本目录约定 → 跟项目走。
- 分两层 = 正确的作用域/生命周期管理。

## 五、自动记忆提炼（main.py:124-154, 472-481）

- 每轮后静默二次调用：MEMORY_PROMPT 专职提取，无新信息回 NONE，
  有则"用户偏好：xxx"追加进 user_memory.md，带去重。
- 动机：职责分离——主模型忙着干活，不兼任记忆管理；
  小调用可控 max_tokens/temperature，失败静默不打扰主流程。

## 六、恢复与命名

- resume：load_session → todo_snapshot 恢复 → memory_block 重拼 system。
- todo 随会话存档（生命周期=会话）；记忆独立文件（生命周期=跨会话）。
- generate_title：首轮后模型起标题，失败 fallback 用户输入前 15 字。

## 七、思考题与答案

**Q1：为什么要 save/commit/discard 三段式，而不是直接写正式文件？**
A：① 退出时用户要选"保存还是丢弃"，先写临时文件后决定更自然；
② 防写一半崩溃——直接写正式文件中途断电会留下半个 JSON（加载报错），
os.replace 原子替换保证"要么旧要么新，无中间态"。这是"先写后改 + 原子
提交"模式，数据库事务和 git 底层同源。

**Q2：sanitize_messages 里 `ids <= found` 为什么是子集判断而不是相等？**
A：ids 是点单声明的 id 集合，found 是后续 tool 消息实际携带的 id 集合。
`ids <= found` 表达"每个点单都找到了结果"。用相等会过度严格——found
可能包含多出来的 id（历史上残留），但只要点单全覆盖，协议就不变量就成立。
目标是"恢复后无孤儿 tool_calls"，不是"id 完全一一对应"。

**Q3：全局记忆和项目记忆为什么要分开存？**
A：生命周期和作用域不同。全局偏好（称呼"紫米芽"、回复风格）跟随用户本人，
换任何项目都应生效；项目约定（构建命令、目录结构）只在当前代码库有效。
混在一起会互相污染：全局偏好塞进项目文件被别的项目误读，或项目约定
被带到不相关的项目。分两层是"按正确的作用域管理状态"。

**Q4：自动记忆为什么是"每轮后静默二次调用"，而不是让主对话直接记住？**
A：职责分离。主对话模型的目标是完成当前任务，让它边干活边判断"该记什么"
会分散注意力，且回复里不适合夹杂"我记住了X"。单独用 MEMORY_PROMPT 的
小调用：职责单一、max_tokens=200 省成本、temperature=0.3 稳定、失败静默
不打扰主流程。和 compact 一样是"小调用换长期价值"。

**Q5：todo 随会话存档（todo_snapshot），而记忆存独立文件，为何不同？**
A：生命周期不同。todo 是"这次任务的进度"，属于会话，随会话恢复才有意义
（修复"任务状态分裂"：换目录/重启后任务清单丢失）；记忆是"跨会话的持久
偏好"，必须独立文件才能跨项目、跨会话长期生效。存档结构的设计依据是
"这段状态的正确生命周期是什么"。

## 八、动手实验（可选）

1. 跑一次会话，中途 Ctrl+C 中断工具审批，然后 exit 保存；用 --resume
   恢复，确认没有报 400（验证孤儿清洗）。
2. 观察 .tmp_xxx.json 的产生与 commit/discard 的替换过程。
3. 让对话暴露一个偏好（如"我喜欢变量名用下划线"），下一轮后看
   user_memory.md 是否自动追加。

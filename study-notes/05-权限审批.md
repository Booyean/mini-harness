# 第 5 层 · 权限审批 学习笔记

> 文件：agent/permissions.py（101 行）
> 对照脚本：day9_demo.py（三任务：只读放行 / 写文件审批 / 写文件拒绝）

## 一、为什么需要审批

- 模型能力含 write_file/edit_file/delete_file/run_bash 等**不可逆**动作。
- 模型本质是"不可信的用户输入"（第 3 层信任边界结论）。
- 权限模型一句话：**只读的随便做，会改东西的要用户点头。**

## 二、分级模型

- **白名单 READONLY_TOOLS**（permissions.py:3-14）：read_file/list_files/grep/
  calculator/web_search/webfetch/update_todo/ask_user/read_image/ocr_image → 自动放行。
- `mcp_` 前缀工具也自动放行（permissions.py:35）。
- 白名单之外（write_file/edit_file/delete_file/run_bash/download_file/
  run_subtask）→ 需审批。

## 三、关键设计：审批插在 loop 层，不在工具函数内

loop.py:251-265 顺序：
```
① check_permissions_batch(tool_infos)   # 先审批
② decisions is None → 返回"用户中止了任务"
③ allowed → registry.execute_tool(name, args)
④ 拒绝 → 也回填 "用户拒绝了此操作"
```

理由：
1. 工具函数要纯净（只干活，不关心谁在调、准没准）。
2. 收口：loop 是唯一执行入口，闸门装在这里任何路径绕不过。

## 四、拒绝也要回填（重要细节）

- 被拒绝 = 回填一条内容为"用户拒绝了此操作"的 tool 消息，而非跳过。
- 原因：第 2 层协议铁律——assistant 的 tool_calls 必须一一配对回填，
  否则产生"孤儿 tool_calls"，下次 API 调用 400。
- "拒绝"不是"跳过"，是"执行一个返回拒绝消息的假结果"。

## 五、批量审批（check_permissions_batch, permissions.py:57）

- 三类分流：白名单 → True；会话规则 → 用记住的结论；其余 → 收集为 pending。
- 只有 pending 打断用户，一次性列出全部待审批项。
- 四选项：
  - y = 全部执行
  - n = 全部拒绝（每项回填"用户拒绝了此操作"）
  - s = 逐个确认
  - q = 中止**整个任务**（返回 None，loop 返回"用户中止了任务"）

## 六、会话权限记忆（_session_rules）

- `/allow <工具名>` → set_rule(name, True)；`/deny` → set_rule(name, False)。
- 模块级全局字典，进程结束即失效 → **会话级**记忆。
- 跨会话偏好存 user_memory.md（第 7 层），两者别混淆。

## 七、思考题与答案

**Q1：被拒绝的工具为什么也占一个 decisions 槽位、也回填"用户拒绝了此操作"，
而不是直接从 tool_calls 里删掉？**
A：两个原因。① 协议铁律：assistant 消息带的 tool_calls 必须与后续 tool 消息
一一对应（id 配对、数量一致）。删掉这条而不回填，消息序列就缺一条 tool，
下次 API 调用直接 400。② 代码对齐：loop.py:257 用 `zip(final["tool_calls"],
tool_infos, decisions)` 三者一一对应遍历，decisions 长度必须等于 tool_calls
长度，否则 zip 会静默截断，导致后面的工具漏执行或错位。所以"拒绝"的语义
实现为"保留槽位 + 回填拒绝消息"，既满足协议又保证索引对齐。

**Q2：为什么 mcp_ 前缀工具默认放行？这个取舍有何风险？**
A：MCP 工具由外部 server 动态注册，harness 无法预知其是否安全，逐个审批
体验差，故默认信任放行。风险：恶意/有 bug 的 MCP server 提供的工具
会被无条件放行执行。更稳妥的做法是给 MCP 工具也加审批或来源白名单，
这是当前实现的一个可改进点（第 9 层展开 MCP 时再评估）。

**Q3：_session_rules 为什么用模块级全局变量而不是存进 messages？**
A：权限规则不是对话内容，不该进入 API 消息（否则会泄露给模型、被模型
"看到并利用"）。它属于 harness 自己的运行状态，进程内一个全局字典即可。
代价是进程重启丢失，但因为它是"会话级"而非"永久"记忆，这正是期望行为。

## 八、动手实验（可选）

3. 让模型一轮同时调用 write_file + run_bash，观察批量审批 y/n/s/q 的效果。
